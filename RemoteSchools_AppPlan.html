08 — Additional Recommendations

Critical Additions to Plan

📄
Content Format: Custom JSON → Compose
Since no WebView is used, lessons must be stored as structured JSON (paragraphs, images, tables, code blocks) and rendered using Compose's custom ContentBlock composable. Java's ContentParser.java converts raw files into typed Kotlin sealed classes.
🔒
Backup Encryption via C++
All backup files encrypted using AES-256-GCM implemented in C++ via NDK. Java JNI bridge exposes encrypt(byte[]) and decrypt(byte[]) to Kotlin. Keys derived from device ID using PBKDF2.
📊
Hilt for Dependency Injection
Use Hilt (not manual DI) to inject ViewModels, Repositories, and UseCases cleanly. Enables easy testing and separation of concerns across the entire app without boilerplate.
⏱️
WorkManager for Auto-Backup
AutoBackupWorker runs every 3 days via WorkManager's PeriodicWorkRequest. Keeps last 3 backups, deletes oldest automatically. Runs only when device is idle and not low on storage.
🧪
Testing Files (Recommended)
Add unit tests for UseCases and Repositories, UI tests for critical screens (Lesson, Quiz). Adds ~20 test files. Use JUnit5, MockK, Compose Test, and Turbine for Flow testing.
🖨️
PDF Rendering (No WebView)
Past papers rendered using Android's built-in PdfRenderer API wrapped in Java helper class. Renders pages as Bitmaps displayed in Compose's Image composable with pinch-zoom support.
🌐
Luganda Localization Strategy
All UI strings in strings.xml and values-lg/strings.xml. Lesson content itself available in both languages as separate content files. Language switch is live (no restart) via DataStore + CompositionLocalProvider.
📱
Low-End Device Optimizations
Target 1GB RAM: lazy Compose lists, image downsampling via Coil with memory caps, ProGuard enabled, APK split by ABI (arm64 vs x86), no unnecessary animations, Room queries on IO dispatcher only.
